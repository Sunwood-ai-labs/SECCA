# トラブル対応

失敗した試行と根拠を残してください。設定を修正した場合は記録を上書きせず、新しい試行へ適用します。

## Podmanやランタイムが使えない

`podman machine list`、`podman system connection list`、`podman --connection "<CONNECTION>" info` を実行してください。稼働中の名前付き接続を明示します。既定の接続を変えたり、ホストのFreeCADへ切り替えたりしないでください。

ランタイムのタグは `localhost/kart-sbx-` で始まる必要があります。公開プロジェクト名を変えても、この検査は変わりません。[はじめに](./getting-started)のタグを使い、解決したイメージIDを記録してください。

## 固定資産の検査が失敗する

コミット済みファイルと `assets/manifest.json` を比較し、誤変更は戻してください。意図した変更なら、新しいプロトコル条件として記録します。ハッシュだけを更新し、旧条件の比較として扱わないでください。

## APIが403・429・タイムアウトを返す

認証情報を表示せず、ゲートウェイとイベントのログを確認してください。記録した接続先・モデル、アカウントの利用権限、クライアント互換性を確認します。403は準備の失敗であり、再現度の点数ではありません。429はその試行での制限応答であり、一般的なレート上限の実測ではありません。

応答状態と時間を保存してください。接続先、有料枠、モデルを自動変更しません。原因を解消して手動で再実行する場合は、別試行として記録します。

## モデルがカタログにない・テキスト入力のみ

未登録モデルには `--model-metadata` を使い、公式の取得元URLと原本ハッシュを保存してください。添付対応と入力形式は事実どおりに保ちます。テキストのみのモデルは、そのままテキストのみとして扱ってください。[試行の実行](./run)を参照できます。

モデルが渡されたファイルを読めば、ツール経由で画素を調べる場合があります。観測した経路を、ネイティブな画像入力と区別して説明してください。CADが生成されなければ失敗として記録し、視覚能力を推定しません。

## CAD検査や描画が失敗する

`evidence/run.events.jsonl`、`evidence/validation.json`、`evidence/render.json` を確認してください。終了コード0やモデルの完了報告だけでは、保存CADの成立は確認できません。集計が見逃した例外をツール本文が含む場合もあります。

候補が後処理前に停止していることと、後処理コンテナが記録済みイメージIDを使うことを確認してください。採点するために元形状を補修してはいけません。未生成や描画失敗は採点不能として残します。

## ドキュメントのページや画像が見つからない

`npm ci`、`npm run docs:check`、`npm run docs:build` を実行してください。公開パスは `/SECCA/`、成果物フォルダは `docs/.vitepress/dist` です。開発サーバーが表示するURLか、公開先の `/SECCA/` を開いてください。ローカルビルドの成功だけでは、Pages公開の成功は確認できません。
