# 再現度を採点する

正本の [`assets/rubric.json`](https://github.com/Sunwood-ai-labs/SECCA/blob/main/assets/rubric.json) を使います。採点対象は見た目の再現度であり、CADの成立や機械としての動作ではありません。

## 項目と目安

| 項目 | 配点 | 見える部位の根拠 |
| --- | ---: | --- |
| 輪郭・比率 | 25 | 全体の低さ、車輪と車体の見た目の比率 |
| 部品の配置 | 20 | 車輪、シート、ハンドル、エンジン、外装の有無と位置 |
| 特徴的な形状 | 30 | バケットシート、ノーズ、バンパー、タイヤ・リム、曲がったフレーム |
| 機械的な細部 | 20 | 操舵機構、エンジン、排気管、駆動・ブレーキ周辺 |
| 配色 | 5 | フレーム、外装、シート、タイヤの色の対応 |

欠落・無関係なら0%、大きく異なる粗い代替形状なら25%、大きな差が残る近似なら50%、局所的な差なら75%、観察できる範囲で近ければ100%を目安にします。各項目の配点へ換算し、見える部位の具体的な理由を添えてください。

## 中立な評価資料を作る

```sh
uv run --frozen python scripts/scores.py packet --trial "trials/my-model-001" --output "reviews/candidate-a"
```

独立評価者には、生成した評価資料の画像・rubric・review templateを渡します。モデル名、過去の点数、実行ログ、他者の採点は渡しません。各評価者が参照画像と標準3方向の生成画像を見る必要があります。

## 3件の評価を集める

1. コーディネータは、他者の評価を読む前に初期採点を保存します。モデル名を知っていることを記録してください。
2. 独立評価者2名を新しいコンテキストで起動します。Codexのエージェントでは `fork_turns="none"` を使います。会話履歴を継承した評価はモデル名非開示と扱いません。
3. 全項目の点数と見える部位の根拠を記録します。0点でなければ加点根拠を、満点でなければ減点根拠を残してください。
4. `context_provenance` に、説明文、読んだ他者評価、タイムゾーン付き日時、署名を残します。盲検という自己申告だけに頼らず、起動方法、資料、確認画像を検証してください。
5. 生成モデルと評価者モデルを別に記録します。評価者の実モデルIDが取得できなければ不明とします。

[評価者向けプロンプト](https://github.com/Sunwood-ai-labs/SECCA/blob/main/references/reviewer-prompt.txt)を使ってください。根拠は `kind` と具体的な `observation` の組で記録します。

## 項目別中央値を合計する

```sh
uv run --frozen python scripts/scores.py aggregate --trial "trials/my-model-001" --reviews "reviews/coordinator.json" "reviews/blind-a.json" "reviews/blind-b.json"
```

各項目で3件の中央値を取り、その5項目を合計します。総点の平均や総点の中央値へ変えてはいけません。Beam実験の項目別中央値は `9 + 9 + 4 + 2 + 1 = 25` です。

3件の原評価、その条件、集計方法、試行数、採点した生成物の数を保存してください。描画画像から正確な寸法、隠れた接続、製造適性を推定しないでください。目視評価を自動画像類似度の計測値として示してはいけません。

## 再現度へ加算しない結果

書き出し、BRepの有効性、ソリッド数、生成時間、記録費用は別に報告し、再現度の点数へ加算しません。出力なし、描画失敗、評価資料不足は採点不能とし、失敗状態を残します。
