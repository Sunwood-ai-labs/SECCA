# 試行を隔離する

OpenCodeだけをコンテナに入れても、ホストのFreeCADで任意Pythonを実行できればホストのファイルを読める。生成モデル、FreeCAD GUI、FreeCAD MCPをまとめて試行専用コンテナに入れる。

1. 候補は `--network none`、UID 10000、読み取り専用のルート、`--cap-drop ALL`、`no-new-privileges` で起動する。ホストのフォルダ、ホーム、Podman/Dockerソケット、公開ポートを与えない。
2. 元画像と実行設定は個別にコピーする。過去の成果物、評価画像、rubric、スキル全体はコピーしない。ランタイムのビルドにもMCPソースと汎用起動コードだけを含める。
3. 通信は候補のループバックHTTPから試行専用Unixソケットへ流す。ソケットのnamed volumeだけを候補に読み取り専用で渡す。別試行のソケットや作業領域は共有しない。
4. ゲートウェイは固定の公開HTTPS APIへ、選択モデルの推論POSTだけを中継する。任意URL、CONNECT、リダイレクト、プライベートIP、別モデル、提供側の履歴・ファイル参照やWeb検索を拒否する。APIキーはゲートウェイだけが持つ。
5. 生成側を停止してからCADを回収する。形状検査と白背景描画は、APIソケットも持たない別の `network none` コンテナで行う。

`--network internal` だけではホスト側ゲートウェイへの到達余地が残るため、候補はネットワークを持たない構成にする。Unixソケットは読み取り専用マウントでも接続できる。そこで許可する操作をゲートウェイ側で検査する。

試行ごとにコンテナ設定、イメージID、入力ハッシュ、標準出力、標準エラー、停止状態、回収CADのハッシュ、後片付けの結果を保存する。APIキーを含む環境変数一覧やsecretの内容を記録しない。

隔離の確認では、別試行の目印、ホストのファイルと環境変数、管理用ソケット、ホストRPC、任意の外部IPへアクセスを試みて拒否を確かめる。FreeCAD MCPのPython実行からも同じ検査を行う。プロキシでは不正な経路・モデル・履歴参照を拒否し、許可した形式の応答を中継できることも確認する。

Windowsホスト版とLinuxコンテナ版は別の実行条件になる。43点の旧記録をPodman実行済みとして扱わない。新しい比較では同じイメージIDを使う。

公開準備で実行した検証は [release-verification.json](release-verification.json)、再実行用コマンドは [ランタイム検証](runtime.md) に記録する。モデル推論を行わず、実FreeCAD MCPでの作成・保存・再読込・白背景描画と、Linuxでのゲートウェイ検査を行った。

移植前の検証条件と結果は [verified-runtime.json](verified-runtime.json)、根拠は `verification` に保存している。新しいランタイムとはイメージIDが異なる過去の記録である。公開版ではホストのホームパスとPodman接続名を置き換えたため、生の原記録ではない。[公開変換マニフェスト](public-export-manifest.json) に元のバイト列と公開版のSHA-256、変換内容を記録している。
